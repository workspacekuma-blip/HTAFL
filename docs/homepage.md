# HTAFL room entrance

The homepage now opens one shared, viewport-scale 3D environment. Its only room
destinations are **Overcome**, **Create** and **Connect**, without visible room or
section numbering. This replaces the separate hero/approach presentations and
repeated homepage world sections. The entrance is a view into Overcome, not a
fourth room. The Five-Path logo, brand tokens, fonts and tagline are unchanged.

Enter Overcome or select any room in the persistent header. The camera moves
through the original architecture; object prompts and Explore objects reveal
readable HTML ideas. Mobile uses the same actual scene and an accessible object
chooser without requiring dragging. Return to entrance reuses the canvas.

About, How It Works, Create, Community, Resources and Get Involved remain real
static URLs. Each opens the same room shell and its existing content in a native
reading dialog. Overcome contains the learning/resource pathway; Create contains
creative expression; Connect contains community and involvement. Read HTAFL
opens mission, challenge examples, values and the participation CTA. Existing
`#mission`, `#challenges`, `#values` and `#get-involved` homepage anchors open that
reading panel. Former creativity/movement/community links now target their
corresponding pages. All reading panels include the shared footer.

Content is never rendered into the canvas. Resource search/filter query state,
challenge empty states, disclosure controls, licensed illustrative images and
local form review remain available. No submissions are transmitted or stored,
and no people, published resources or community stories have been invented.

See [the room implementation guide](immersive-world.md) for geometry, controls,
accessibility, performance, fallback and verification. The former hero and spatial
section helpers remain in the repository but are not loaded by these routes.
Without JavaScript, the homepage offers three native room links and readable
mission/participation content; supporting routes retain their ordinary HTML.
